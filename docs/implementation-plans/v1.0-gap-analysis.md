# v1.0 Feature Gap Analysis: playwright-rust vs playwright-python

**Last Updated:** 2026-08-17

**Baseline:** playwright-rust v0.17.0 vs playwright-python (Playwright v1.62+)

## Goal

Comprehensive API gap analysis comparing this repo's Rust bindings against the official Playwright Python bindings. Organized by priority to guide v1.0 development.

---

## Coverage Summary

**Accuracy correction (2026-08-11):** this document's checklist reported
itself complete while `waitForFunction` — a core Page/Frame API in every
binding — was entirely unimplemented. The gap was found during the 1.62
driver bump and closed on `main` (`e3e4b28`), including the 1.62
locator-scoped form. Treat the checklists below as a strong-but-not-proven
inventory: the reliable parity check is diffing the protocol spec directory
against what the crate sends, which is how this one surfaced.

Full Python API parity was achieved in v0.12.0. v0.13.0 (shipped
2026-05-23) closes the remaining Playwright 1.59 gap
— `Page::screencast`, `Debugger`, `Page::pick_locator`, CDP event side
on `CDPSession`, `AriaSnapshotOptions`, `Tracing.start({live: true})`,
`Page::aria_snapshot`, `Locator::normalize`, `LaunchOptions::artifacts_dir`
— and adds two companion crates (`playwright-rs-macros` for the
compile-time-validated `locator!()` macro, `playwright-rs-trace` for
programmatic trace-file consumption). The bundled driver was bumped
from 1.59.1 → 1.60.0 on `main` on 2026-05-16; the bump is source-compatible
(none of the upstream-removed 1.60 APIs were exposed in this crate),
and the new 1.60 surface (HAR Tracing API, `Locator::drop`, screenshot
`mask`/`animations`/etc., expanded BrowserContext lifecycle events,
page-level ARIA-snapshot assertion, and the smaller polish options) has
since been implemented in full under "v0.14.0 — Playwright 1.60
Completeness" below — every item is checked.

The driver was bumped to **1.61.1** (commit `40ceb69`, 2026-07-04) and
that surface shipped in **v0.15.0**: WebAuthn virtual credentials
(`BrowserContext::credentials()`), `WebStorage`
(`Page::local_storage()` / `session_storage()`),
`APIResponse::security_details()` / `server_addr()`,
`ConnectOverCdpOptions::artifacts_dir`, and the screencast `cursor`
option + frame `timestamp`.

The driver is now **1.62.1**, shipped in **v0.16.0** (2026-08-17) and
carried unchanged by **v0.17.0** (2026-08-23), which unified event delivery
and made `--with-deps` opt-in on Linux without touching API surface. Its
language-binding-relevant surface — `wait_for_function` on Page/Frame
(a genuine pre-existing gap, see the accuracy correction above) and its
1.62 locator-scoped form, `Page::evaluate_with_callback()`, WebAuthn
passkeys and IndexedDB in storage state, `APIResponse::timing()`, WebP
screenshots, and the `Scroll` action option — is fully implemented. That
release also carried a wire-contract change (1.62 moved `timeout` out of
method params into the request metadata envelope) and breaking
storage-state changes; both are detailed in
[`crates/playwright/CHANGELOG.md`](../../crates/playwright/CHANGELOG.md)
under `[0.16.0]`.

playwright-rust covers the **complete Playwright 1.62 API surface** and
is at parity with playwright-python.

v1.0.0 follows after multi-month dogfooding with real-world projects —
API polish, ergonomics refinements, and performance tuning rather than
new surface area.

## P0 — Critical for v1.0

### Locator: `get_by_*` Methods

These are *the* modern Playwright locator pattern. Without them, users cannot write idiomatic Playwright tests.

- [x] `get_by_role(role)` — Locate by ARIA role (most important)
- [x] `get_by_text(text)` — Locate by text content
- [x] `get_by_label(text)` — Locate by associated label
- [x] `get_by_placeholder(text)` — Locate by placeholder text
- [x] `get_by_test_id(test_id)` — Locate by test ID attribute
- [x] `get_by_alt_text(text)` — Locate by alt text
- [x] `get_by_title(text)` — Locate by title attribute

These must also be available on **Page** and **Frame** (they delegate to the main frame's locator).

### Locator: Filtering & Composition

- [x] `filter()` — Narrow locator with additional conditions (has_text, has, etc.)
- [x] `and_(locator)` — Match both this AND another locator

- [x] `all()` — Return array of locators for each match

### v0.14.0 — "Playwright 1.60 Completeness"

✅ **Shipped 2026-06-13.** Tracks the new
API surface introduced upstream in Playwright 1.60 (released 2026-05-11).
Driver bumped on `main` 2026-05-16; the Rust bindings for the new
methods/options below are all implemented. Priority labels match the
P0/P1/P2/P3 buckets above.

**P1 — High value:**

- [x] `Locator::drop(options)` — simulate external drag-and-drop of files and/or MIME-typed data onto an element. Dispatches `dragenter`/`dragover`/`drop` with a synthetic `DataTransfer`. Distinct from `drag_to(target)` (intra-page drag); the canonical primitive for upload-zone tests. `DropOptions` carries `files: Vec<FilePayload>` and `data: Vec<(mime, value)>` plus optional `position`/`timeout`. End-to-end tested against a real drop zone.
- [x] `BrowserContext` lifecycle event mirrors — `on_download`, `on_frame_attached`, `on_frame_detached`, `on_frame_navigated`, `on_page_close`, `on_page_load`. Not wire events on the context channel; the binding forwards each page's events to context-level handlers (wiring current and future pages), matching how upstream clients synthesize them.
- [x] `Browser::on("context")` — `Browser::on_context`, fired when a new context is created on the browser (a real wire event, like `on_disconnected`); lets framework code observe context creation without threading the `new_context()` return value through.
- [x] `Tracing::start_har(path, options)` / `Tracing::stop_har()` — first-class HAR recording with `content`, `mode`, `url_filter`, `resources_dir` options. `.zip` paths bundle bodies; other paths extract the `.har` JSON via the new `LocalUtils::har_unzip`. Explicit start/stop rather than a `Drop` guard (async `Drop` is not viable in Rust); state is stashed on the `Tracing` object so `stop_har` needs no path, matching the upstream API. Demonstrated in site-e2e (the dogfood run publishes its HAR as a receipt).

**P2 — Locator / Page / Assertion polish:**
